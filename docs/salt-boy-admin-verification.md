# SALT BOY 投稿・管理画面の検証 (2026-11-21)

## 実装と運用

- 通常の在庫投稿は自動反映。管理者による承認とは、既存の承認履歴で区別する。
- 形態の一括送信は1回。実店舗は2店舗以上・5分以内の6回目以降を承認待ちにする。
- 同じブラウザー・同じ店舗・同じ商品区分への新規投稿は3分以内なら拒否。同じリクエストIDの再送は先に照合し、重複登録も件数加算もしない。
- 同じIP・同じ店舗・同じ商品区分は10分以内5回まで。IPはHMAC化し、SALT BOY用テーブルに保存する。
- 同じIP・同じブラウザー・同じ店舗区分の10分以内の連投は、実店舗15回目/オンライン30回目で直近分を承認待ちに戻し、次から一時拒否する。既存So Honey APIの条件を一括投稿単位へ引き継いだ。
- 実店舗の50枚以上はコメント必須・承認待ち。オンラインは枚数入力を受け付けない。
- 本人削除は既存ブラウザーIDによる所有確認を経由する。同じブラウザーの投稿を一覧し、個別に削除できる。別ブラウザーへの復旧は対象外。
- SALT BOYの管理画面内に投稿一覧、操作履歴、初週情報、セキュリティ履歴を配置。却下を復元した場合は承認待ちへ戻す。
- 初週情報は実店舗の閉店/指定時刻とオンラインの発送/到着日付範囲を分ける。特典有無・まとめ買いも在庫と同じ区分で保存する。
- 初週情報の入力・表示接続は、各社条件を含めた初週判定の完成とは別。判定仕様の検証は統合TODOの第2節に残す。
- So Honeyの公開画面・API・DB関数は維持。SALT BOYの管理画面を開く際の旧投稿一覧・旧確認待ち・旧削除履歴の先読みを停止した。
